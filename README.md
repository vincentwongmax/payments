# 付款記錄

把付款截圖整理成可編輯的記錄。上傳圖片後自動辨識金額與付款時間，全部資料存在你自己的瀏覽器裡，**不需要網路、不上傳到任何伺服器**。

## 功能

- **人物管理**：新增／修改／刪除，可指定哪一位是「自己」；付款人預設就是自己，受益人可多選。按「修改」會看到這個人被記錄用到的次數（**付款人 XX 筆、受益人 XX 筆**分開算），以及**合併到另一位人物**的功能
- **人物保護**：已經被記錄用到的（付錢人或受益人）**不能刪除**，會跳出視窗說明還有幾筆在用（付款人／受益人分開算，人物列上也有「N 筆」標籤）；記錄指到的人物如果因為匯入對不到等原因不見了，重新整理時會用記錄裡存的名字**自動補回**
- **批次上傳**：一次選多張圖片，依圖片本身的時間（EXIF 拍攝時間，讀不到才用檔案時間）排序後依序新增
- **貼上圖片**：可以按「貼上圖片」讀剪貼簿，或直接在頁面上按 Ctrl+V
- **格式自動處理**：iPhone 相機的 HEIC 照片在 iPhone 上會自動轉成 JPEG；讀不到的格式會擋下來並說明原因，不會產生破圖的記錄
- **手動新增**：沒有圖片也能先開一筆記錄，金額與時間自己填。標題會自動編號（`手動新增1`、`手動新增2`…，號碼不重用）；之後點左邊的「**無圖**」就能補上圖片，補完會重新辨識金額與時間（你已經自己填過的金額／時間不會被蓋掉）
- **離線 OCR**：辨識付款時間與金額（中英文），完全離線執行
- **多幣別**：同一張圖有多個金額（例如 CNY、MOP）時可以挑選要用哪一個；預設幣別隨時可設，還沒上傳也可以先選
- **看圖**：點縮圖或「圖片」按鈕開啟檢視視窗，可放大／縮小／還原（也支援 Ctrl+滾輪）
- **自動去重**：以 MD5 比對，完全相同的圖片不會重複新增
- **資料保存在本機**：存在瀏覽器 IndexedDB，重新整理或關掉瀏覽器都不會不見
- **完全離線**：用過一次之後就註冊了 Service Worker，**沒網路也打得開、也能辨識**。手機可以「加到主畫面」當 App 用（iOS 只有加到主畫面才不會被「7 天沒用就清資料」的規則清掉）
- **設定頁**：右上角「**設定**」（在「重置」左邊）會切到一整頁的設定，裡面有：
  - **備注分類管理**（平常是收起來的，按標題才展開）：新增／點名稱改名／上下調整順序／刪除
  - **分享連結**：貼上 `?persons=…&currency=…&notes=…` 後按「套用」。**貼上的內容會一直留在框裡，連重置也不會消失**
  - **更新**：「檢查更新並重新載入」。加到主畫面的 App 沒有網址列、也沒有下拉重新整理，更新就按這個
  - **資料統計**：幾筆記錄、幾位人物、幾個分類、瀏覽器用了多少空間、永久儲存與離線快取狀態
  - **版本資訊**：建置時間（跟電腦上看到的一樣就代表手機是最新版）
- **匯出／匯入**：單一 JSON 檔（圖片以 base64 夾在裡面），匯入採合併、不覆蓋現有資料。**一次可以選多個 JSON**，會依序匯入（需要對齊人物時，一個一個問你）
- **來源與序號**：每筆記錄左邊顯示「來源-序號」（例如 `本機-3`、`一月帳單-1`）。自己上傳的來源是「本機」，匯入的用 JSON 檔名當來源，**點序號就能重新命名整個來源**
- **人物對齊與合併**：匯入時同一個人寫法不同（Vincent / vincent、Ben / 餅）可以指定對應到現有人物，對應結果會記成別名；已經存在的重複人物也能一鍵合併
- **分享連結**：在網址加上 `?persons=Vincent,Ben,Ken&currency=CNY`（或寫在 `#` 後面），開啟時自動建立缺少的人物並設定預設幣別；加到主畫面的 App 拿不到參數時，也可以在人物卡片上貼連結套用
- **重置**：可以勾選要保留人物、預設幣別、備注分類；付款記錄、圖片一律清空
- **備注分類（常用字串）**：備注輸入框**右邊內嵌一個圖示按鈕**（跟付款時間的日曆按鈕同一個做法），按下去會列出常用分類，點一下就填進那一筆的備注。內建 10 個預設（吃_早餐、吃_午餐、…、飲_廢水( )），要新增或整理就到「設定 → 備注分類管理」；也可以從分享連結用 `notes=` 帶進來
- **重置可以選保留**：重置時可以勾選要保留「人物／預設幣別／備注分類」，不勾的就清掉；付款記錄與圖片一律刪除
- **RWD**：手機、平板、電腦都能用。手機版（寬度 ≤ 560px）的差別：記錄**由下往上排**（最新、序號最大的在最上面，剛上傳的馬上就看得到）、縮圖上方多一張只看圖片上 1/3 的預覽、看圖時下面那排是「縮小／放大／還原／關閉」、點圖片本身等於關閉。
- **手機不會被誤放大**：整棵樹都設了 `touch-action: manipulation`，另外 App 裡還有一道守衛：**同一個位置在 350 毫秒內被點第二下就擋掉那一下的預設行為**（Safari 只認手指底下那一個元素，遇到 `disabled` 按鈕或非互動元素時 `touch-action` 就失效，所以不能只靠 CSS）。滑動結束順手點一下、不同位置的快速點擊、雙指縮放都不受影響。另外「正在忙」的按鈕也刻意不用 `disabled` 屬性（iOS 的 disabled 按鈕收不到觸控事件），改用 `.is-busy` ＋ `aria-disabled`，看起來一樣灰但還是活的元素。

## 快速開始

```bash
npm install     # 第一次要先裝套件
npm run dev     # 開發模式，開 http://127.0.0.1:5173/
```

其他指令：

```bash
npm test          # 執行邏輯自我檢查（EXIF、OCR 解析、MD5、匯出匯入往返）
npm run build     # 打包到 dist/
npm run preview   # 預覽打包結果
```

專案附了一支 commit 前會自動跑 `npm test` 的 hook，沒通過就擋下這次 commit。第一次取得專案時要先啟用：

```bash
git config core.hooksPath .githooks
```

> ⚠️ 一定要用本機伺服器開啟（`npm run dev` 或 `npm run preview`）。
> 直接雙擊 `dist/index.html`（`file://`）會壞掉：IndexedDB 與 OCR worker 在 `file://` 下無法運作。

## 離線 OCR

OCR 引擎（Tesseract.js）與中英文語言包已經放在 `public/tesseract/`（約 40.9 MB），執行時不會連外網。三個 wasm 變體都放了，讓新舊瀏覽器都能跑。

- **每張圖跑兩種辨識模式**：PSM 3（區塊模式）負責密集文字與日期，PSM 11（稀疏模式）負責付款 App 那種浮動的大字金額。實測只有 PSM 11 讀得到那行大字，也只有 PSM 3 讀得準密集帳單文字，所以兩份結果都會解析後再合併。
- **兩個 worker 並行**跑這兩種模式，時間約等於跑一次（實測 15 張從 40.8 秒降到 25.6 秒，結果完全相同）。代價是記憶體約翻倍，所以手機記憶體較小時（`navigator.deviceMemory` 小於 4GB）會自動只用一個 worker 依序跑；第二個 worker 建不起來時也會自動退回單一 worker。
- 用**完整版**語言模型（`4.0.0`，非量化版），中文辨識比精簡版準；代價是首次載入約 30 MB。
- **餵給 OCR 之前會先轉成灰階**。實測支付寶那種「藍底白字」的付款成功畫面，彩色原圖整張進去時上半部（付款成功、金額、收款方）**一個字都讀不到**，只剩下面白底的廣告；轉灰階後整張都讀得到。反相也有同樣效果，但灰階對白底黑字的圖最中性。
- 第一次辨識要載入引擎與語言包，會慢一點，之後每張圖約 1.7 秒；同一個分頁之後就快了。
- **首次載入的流量**：語言模型約 30 MB（解壓後存在 IndexedDB，之後不會再下載）＋ OCR 引擎約 3.8 MB（只下載手機實際用到的那一個 wasm 變體，存在 Service Worker 快取）。之後**完全離線**也能辨識。
- **90 秒逾時**：引擎或單張辨識卡住會直接報錯並重建 worker，不會無聲無息卡在 0%。
- OCR 不是 100% 準。狀態分成「已辨識」「只讀到金額」「只讀到時間」「沒抓到，請手動填」，**看到橘色標籤就代表有東西要自己補**；失敗的卡片有「重新辨識」按鈕。

### 金額是怎麼挑的

付款畫面通常有兩種金額：**大字顯示的實際付款金額**，和**小字的訂單金額／折扣**。所以要挑的是大字那個。

- **字級大的優先**：從 tesseract 的文字框取出每個數字的字元高度，實際付款金額的字會明顯比訂單金額大（實測大字 51、小字 32）。取的是「數字字元高度的中位數」，不是整個文字框的高度——框高會被破折號之類的標點灌水（折扣那行 `-#0.07` 整框高 59，數字其實只有 32）。同一個數字在畫面上出現很多次時（縮圖、列表、標題）再取一次中位數，避免某一次被讀成超大字就把真正的金額壓下去。
- **數量詞不算金額字級**：`共5件` 的 5 是「幾個」不是多少錢，它的字框常常特別大，不會拿來當金額的字級。
- **小數點被讀丟時以小數點為準**：同一個數字同時出現「8.92」與「892」兩種讀法時留有小數點的那個——tesseract 幾乎不會無中生有生出一個點，但漏掉一個點很常見。
- **幣別不同時並存**：像 `MOP 192.74` 與 `(CNY 158.00)` 會兩個都留著讓你挑；設了「預設幣別」就以那個幣別為準，優先於字級。
- 排除明顯不是金額的：數字後面接 `积分`／`%`／`折`／`=`，或前面接 `号`／`凭证`／`卡`／`方式` 的；超過 7 位整數（交易流水號）；緊貼英文字母的（`CP784M`）。
- 中文之間的空格會被忽略，所以 `订 单 金 额` 認得出是「訂單金額」；`¥` 被讀成 `y` 或 `羊` 時（`合 计 y 46.39`）也認得出來。
- **`-¥239.93` 這種負號不是折扣**：雲閃付之類的 App 用負號表示「付出」。所以負號不會被排除。
- 一張圖多個候選時會列出來讓你點，挑錯可以直接點正確的那個。

## 分享連結（自動建立人物）

在網址後面加參數，開啟時就會自動建立缺少的人物並設定預設幣別：

```
http://127.0.0.1:5173/?persons=Vincent,Ben,Ken&currency=CNY&notes=吃_早餐,打車(去程)
```

- `persons`：人名，用逗號分隔。中文逗號 `，`、頓號 `、`、分號 `；` 也可以。最多 30 個，每個 40 字，控制字元會清掉。
- `currency`：三位英文字母的幣別代碼，例如 `CNY`、`MOP`、`HKD`。格式不對就忽略。
- `notes`：備注的常用分類，規則跟 `persons` 一樣可分隔、會去重。**從連結加進來的不會因為「重置」而消失。**

規則：

- **已經有的人不會重複建立**，大小寫與別名都會比對（連結寫 `ken` 會對到現有的 `Ken`）。
- **連結不會預設誰是「自己」**，等你上傳圖片或新增記錄時才會問你。
- **重複開同一個連結不會一直新增**，只有真的有新增或改動才會顯示提示。
- **同一組名單只套用一次**：之後就算你把連結帶進來的人物刪掉，重新整理也不會自動加回來。要讓同一個連結重新生效，得先按「**重置**」（會清掉全部資料）。
- 沒帶參數的一般開啟完全不受影響。
- 參數會留在網址上，所以可以直接把網址列的連結複製給別人。
- **也支援寫在 `#` 後面**：`https://…/payments/#persons=Vincent,Ben&currency=CNY`。加到手機主畫面時 iOS 有可能只保留 `#` 後面的部分，所以兩種寫法都支援。
- 加到主畫面的 App 如果拿不到參數（人物清單是空的），就到「**設定 → 分享連結**」把原本的連結貼上去按「套用」。**貼上的內容會一直留在框裡（重置也不會清空）**，要改自己改掉就好。

> 提醒：這只是「設定連結」，不會建立付款記錄，也不會帶入金額。金額一律由上傳的圖片辨識或你自己填。

## 加到手機主畫面（PWA）

用 Safari／Chrome 開網站 → 分享 → 「加入主畫面」，之後就有自己的圖示，**完全沒網路也能開、也能辨識**。

- **第一次載入**會下載約 34MB（語言模型 30MB ＋ OCR 引擎 3.8MB），之後存在手機裡，不會再下載。
- **更新**：連著網路打開就會抓到新版；已經開著的那一頁就到「**設定 → 更新 → 檢查更新並重新載入**」。
- **`start_url` 刻意不寫**：iOS 建立主畫面 App 時會用 manifest 的 `start_url` 當開啟網址，一寫死就會把分享連結的 `?persons=…&currency=…` 丟掉。不寫 `start_url` 時，預設是「當時那一頁的網址」，參數才會留下來。
- **iOS 的主畫面 App 通常有自己獨立的儲存空間**（跟 Safari 分開，這是 iOS 的設計）。如果你之前在 Safari 已經有記錄，加到主畫面後看到的是空的，請用「**匯出**」下載 JSON、再到主畫面 App 裡「**匯入**」。
- iOS 對「沒加到主畫面」的網站有「7 天沒用就清掉資料」的規則；加到主畫面之後就不受影響。

### 誰是「自己」

付款記錄需要知道「自己」是誰（付錢人預設就是他）。所以：

- **上傳圖片、貼上圖片、新增記錄之前**，如果還沒設定「自己」，會彈出視窗要你選一位，選完才會繼續原本的動作。
- 這個時候按取消，原本的動作就整個放棄（不會偷偷建立記錄）。
- 如果**連一個人物都沒有**，會先開「新增人物」讓你建立；第一個人物預設就勾好「這是我自己」，存檔後會自動接續原本的動作。
- 選好之後，之前付錢人空白的記錄也會一併補上。
- 分享連結建立的人物**不會自動變成自己**，一定要你親自選。

## 圖片格式

| 來源 | 結果 |
|---|---|
| iPhone **截圖**（PNG） | ✅ 直接支援，不需要任何處理 |
| 相機照片（JPEG） | ✅ 直接支援 |
| 相機照片（**HEIC**）**在 iPhone 上上傳** | ✅ 自動轉成 JPEG 再存 |
| 相機照片（**HEIC**）**在電腦版瀏覽器上傳** | ❌ 讀不到，會擋下來並告訴你原因 |
| 其他（WebP、GIF 等） | 看瀏覽器支援度，讀不到的會擋下來並說明 |

HEIC 從 iOS 11 起就是 iPhone 相機的預設格式，但**除了 Safari 17+，沒有瀏覽器能解 HEVC 編碼的 HEIC**——`<img>`、`createImageBitmap()`、canvas 在 Chrome／Firefox／Edge 一律失敗。這是瀏覽器層級的限制，不是本程式的問題。

所以本程式的做法是：

- **在 iPhone 上**：偵測到 HEIC 就用 canvas 轉成 JPEG（品質 0.92）再存，之後在電腦上也看得到。轉檔後**保留原本的檔名**方便你認出是哪張照片，但內容已經是 JPEG（有損壓縮）。
- **在電腦上**：轉檔會失敗，這時會**擋下來不建立記錄**，並顯示「略過 N 張這個瀏覽器讀不到的圖片…」。好圖不受影響，照常辨識。
- 長邊超過 4096 的照片會縮到 4096（48MP 的照片 OCR 會慢到不能忍受；一般 12MP 的照片不受影響）。
- 判斷格式看的是**檔頭 16 bytes**，不是副檔名或 MIME——改名叫 `.jpg` 的 HEIC 一樣會被處理。AVIF 也共用同樣的檔頭但到處都解得到，所以刻意排除。

> 圖片本身的時間：只有 **JPEG** 讀得到 EXIF 拍攝時間。PNG 截圖與 HEIC 會退回使用檔案時間，所以排序與「付款時間」的辨識不受影響（付款時間是從圖片內容 OCR 出來的）。

## 資料存放與備份

資料只存在這台裝置的瀏覽器裡（IndexedDB，資料庫名稱 `payment-records`）。換瀏覽器、換裝置、或清除瀏覽器資料都會看不到。

要備份或搬到別的裝置，用「**匯出**」下載 JSON，再到另一台按「**匯入**」。

- 匯出時圖片會**壓縮**：等比縮到短邊至少 700px（長寬比不變，1290×2796 → 700×1517），再降 JPEG 品質，讓每張圖不超過原檔的 1/3。原本存在瀏覽器裡的圖片不受影響，只有匯出檔裡的是壓縮版。
- 匯出檔含圖片，所以檔案可能不小。
- 匯出檔名會帶上「自己」的名字，例如 `付款記錄-Vincent-202609210435.json`，方便分辨這份是誰的記錄。還沒設定「自己」時就是 `付款記錄-202609210435.json`。
- 匯入是**合併**：已經有的記錄（MD5 相同或 id 相同）會略過，不會覆蓋現有資料。
- 一次可以選**多個** JSON 檔，會一個接一個匯入；每個檔案要對齊人物時都會停下來問你，選完才換下一個。最後的提示會總結「幾個檔案、新增幾筆」。
- 匯入進來的記錄，**來源會自動設成那個 JSON 檔的檔名**（去掉 `.json`），方便跟自己的記錄區分。
- 在乾淨的環境匯入自己匯出的檔案，資料會和匯出前完全一樣（`npm test` 有驗證這件事）。

### 來源與序號

每筆記錄左邊有一個「來源-序號」標籤，序號在**同一個來源內從 1 開始**：

- 自己上傳或手動新增的 → 來源是「本機」，例如 `本機-1`、`本機-2`。
- 匯入 JSON 的 → 來源是那個檔名，例如 `一月帳單-1`、`一月帳單-2`；跟自己上傳的分開編號。
- **點那個標籤**就能重新命名來源，同一個來源的記錄會一起改。改成已經存在的來源名稱，就等於把兩批合併編號。
- 來源名稱會一起存在本機，重新整理不會不見。

> 來源名稱不會寫進匯出檔——它是這台裝置上的分類標籤，所以重新匯入時會以當時的檔名為準。

### 人物對齊

同一個人在不同檔案裡可能寫得不一樣。匯入時：

- **只差大小寫或頭尾空白**（`Vincent` / `vincent` / `" Ben "`）會**自動**視為同一人，不會問你。
- **完全不同的寫法**（`餅` / `Ben`）會跳出一張「對齊人物」的清單，讓你自己選要
  「對應到現有人物」還是「建立新人物」。目前還沒有任何人物時（第一次匯入）不會問，全部視為新人物。
- 對應過的寫法會記在該人物的**別名**裡，**下次匯入同一個寫法就自動套用，不會再問**。
  記錄一律歸到原本那個人的名字與 id 上（以最初的名字為準）。
- 別名可以在人物的「修改」視窗手動增刪，用逗號分隔。名字與別名不能跟別的人物重複，否則會擋下來。

### 合併重複的人物

如果 `Ben` 和 `餅` 在你用這個功能之前就已經變成兩個人了，打開其中一位的「**修改**」，最下面有「**合併到另一位人物**」：選好對象按「合併」，記錄裡的付錢人與受益人都會一起轉過去，原來的名字會變成別名，所以之後匯入同樣的寫法還是會自動對上。（合併前會再確認一次，合併無法復原。）

## 部署到 GitHub Pages

用 `npm run deploy`：它會先跑測試、建置，再把 `dist` 的內容推上 `gh-pages` 分支。**不需要 GitHub Actions。**

1. 在 GitHub 建立一個 **public** repo，把 `main` push 上去。
2. 到 repo 的 **Settings → Pages**：**Source** 選 **Deploy from a branch**，分支選 **gh-pages**、資料夾選 **/(root)**。
3. 之後每次改完，跑一次 `npm run deploy` 就會更新網站。網址是 `https://<你的帳號>.github.io/<repo>/`。

`scripts/deploy.mjs` 會在系統暫存資料夾建立一個獨立的 repo 來產生 `gh-pages` commit，**專案本身的 git 歷史完全不受影響**，也不會污染你的工作區。

> ⚠️ **發布前務必確認你的付款截圖沒有進版控。** `.gitignore` 已經擋掉 `付款記錄/`、`圖片/` 與所有圖片副檔名，但如果你把截圖放在別的位置，請自己確認 `git add -A --dry-run` 的輸出裡沒有圖片。
>
> 網站是公開的，但**所有資料只存在使用者自己的瀏覽器**（IndexedDB），不會上傳到任何伺服器。
>
> 第一次載入會下載約 34MB（語言模型 30MB ＋ OCR 引擎 3.8MB），之後存在瀏覽器裡，**完全沒網路也能用**。手機使用者請留意第一次的流量。
>
> 改版後：手機端下次連網打開 App 就會抓到新版（換頁是先試網路、失敗才用快取）；已經開著的那一頁就到「設定 → 更新」按一下。

## 已知限制

- OCR 金額辨識需要人工確認，這是技術本質，不是 bug。
- 沒有 EXIF 的圖片（例如多數 PNG 截圖）只能用檔案時間排序。
- 資料綁在單一瀏覽器上，跨裝置請走匯出／匯入。
- 大量圖片（數百張以上）會佔用不少瀏覽器儲存空間，建議定期匯出備份。
